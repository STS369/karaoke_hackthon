## 💡 背景・課題 (Why)
カラオケに行った際、「次、何を歌おう？」と悩み、履歴を探す時間を無駄にしてしまう経験から着想を得ました。  
**「選曲の迷い」をなくし、歌う時間を最大化する**ために、自分の聴取履歴から瞬時にセットリストを作れるアプリを開発しました。

---

## 📱 主な機能 (Features)

### 1. Spotify連携によるパーソナライズ
- OAuth認証を用いてログインし、「最近聴いた曲」「お気に入り」「おすすめ曲」を自動取得・表示

### 2. 直感的なプレイリスト作成
- 気になった曲を「リストに追加」ボタン一つでストック  
- カラオケ店での入力をスムーズにするための「セットリスト」を瞬時に構築

### 3. メモ・スコア機能
- 曲ごとに「採点結果」「歌った感想」を記録  
- 次回のカラオケに活かせるデータベースとして活用可能

---

## 🛠 使用技術 (Tech Stack)

### Frontend
- **Language**: JavaScript  
- **Framework**: React (Vite)  
- **Styling**: CSS（Neon UI Design）

### Backend
- **Language**: Python 3  
- **Framework**: Flask  
- **Libraries**: Spotipy（Spotify API wrapper）, Flask-CORS  
- **Authentication**: OAuth 2.0（Authorization Code Flow）

## 🧑‍💻 私の担当箇所 (Role)
**フロントエンドとバックエンドの連携（統合）担当**

本プロジェクトでは、主に **React（フロントエンド）と Flask（バックエンド）をつなぐ役割**を担当しました。  
画面側の実装を進めながら、「データがどこから来て、どこへ渡るのか」を意識して開発を行いました。

### フロントエンド × バックエンドの API 連携
- React から Flask API へリクエストを送り、結果を画面に反映する処理を実装
- JSON データの構造を確認しながら、「どの値を・いつ・どう使うのか」を整理して開発
- 通信エラーやデータ未取得時にも画面が破綻しないよう、最低限のエラーハンドリングを意識

### Git / チーム開発について
- Git は主に **自分の作業内容を正しく反映するための利用**が中心
- 大規模な管理は行っていませんが、

## 担当・工夫した点

本プロジェクトでは、**フロントエンドの土台設計**および**バックエンドのコア機能実装**を担当しました。

初めてのチーム開発であったため、特に以下の点に注力しました。

- **フロントエンドの構成設計**  
  コンポーネント構成や画面遷移を意識し、後から機能追加・修正がしやすい土台づくりを行いました。

- **直感的に操作できるUI設計**  
  初見のユーザーでも迷わず使えるよう、操作フローを簡潔にし、視覚的にも分かりやすいUIを意識しました。

- **機能実装**  
  「お気に入り曲」機能および「おすすめ曲」機能を実装し、ユーザー体験の向上を図りました。

- **バックエンドのエラー対応**  
  API通信時のエラーや想定外のレスポンスに対応するため、エラーハンドリングを意識した実装を行いました。

### 「おすすめ曲」機能に関する工夫

「おすすめ曲」機能の実装では、当初 **他者が公開している Spotify 上の「〇月のおすすめ曲」プレイリストを取得して表示する方針**を検討しました。しかし、API制約や取得条件の問題により、安定してデータを取得できませんでした。

そこで方針を切り替え、**自分たちで Spotify 上に専用の「おすすめ曲」プレイリストを作成**し、それを Spotify API と連携して Web アプリに組み込む形で実装しました。

この対応により、以下を実現しました。

- 安定したデータ取得
- プレイリスト内容の柔軟な更新
- 機能要件を満たした形での実装

## 🔥 こだわった点・苦労した点 (Challenges)

### 1. 実装スピードを最優先した AI 活用とリソース配分

今回、バックエンド技術（Flask）は未経験の領域でした。  
短期間のハッカソンで導入する必要があったため、**「期間内に動くプロダクトを完成させること」**を最優先に判断しました。

- **AIの活用による実装効率化**  
  複雑な処理ロジックや構文生成は AI を活用し、実装スピードを向上

- **人が担うべき部分への集中**  
  生成コードの入出力仕様やインターフェースの整合性を重点的に確認し、  
  フロントエンドとの連携確認やバグ検証に時間を割くことで、チーム全体の生産性向上に貢献しました。

### 2. 「データは取得できているのに表示されない」バグの解決

バックエンドでは正常にデータ取得できているにもかかわらず、  
フロントエンド画面が真っ白になる問題が発生しました。

ブラウザの検証ツールとサーバーログを突き合わせて調査し、  
**型定義の不整合**や**非同期処理のタイミングのズレ**を特定。  
データ構造と処理順序を修正することで、問題を解決しました。

### 3. 「カラオケボックス」を意識した UI デザイン

UIデザインでは、**ダークモード × ネオンカラー**を基調とし、  
「アプリを開いた瞬間にカラオケボックスに入ったような高揚感」を得られることを目標に設計しました。

視認性と雰囲気の両立を意識し、エンタメ性の高い体験を提供するUIを目指しました。
